# MessagesPlaceholders: Plantillas dinámicas de mensajes

Hasta ahora hemos visto cómo utilizar las plantillas de prompts para introducir variables de texto utilizando el formato de `PromptTemplate` y `ChatPromptTemplate`. Con esto, se puede resolver un porcentaje bastante alto de los casos prácticos a los que nos enfrentamos.

Sin embargo, **¿Qué sucede si queremos introducir una lista completa de mensajes en lugar de una simple cadena de texto?**

Por ejemplo, si queremos introducir un historial de mensajes que ha mantenido el usuario con nuestro LLM (para mantener el contexto de la conversación), usar variables dinámicas de texto simples presenta limitaciones. Pasar todos los mensajes concatenados como un solo bloque de texto es una aproximación un tanto rudimentaria y menos efectiva.

Aquí es donde entran en juego los **Messages Placeholders**.

## ¿Qué son los Messages Placeholders?

Un `MessagesPlaceholder` es un mecanismo de LangChain que permite insertar un listado dinámico de mensajes (como un historial de chat completo) dentro de una plantilla de prompt.

### ¿Cómo utilizar MessagesPlaceholders?

Para utilizarlo, necesitamos importar por un lado `ChatPromptTemplate` y por otro `MessagesPlaceholder` desde `langchain_core.prompts`:

```python
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder
from langchain_core.messages import HumanMessage, AIMessage, SystemMessage
```

Luego, podemos definir nuestra plantilla sustituyendo un bloque de mensajes por el Placeholder indicando el nombre de variable que va a recibir esta lista de mensajes:

```python
chat_prompt = ChatPromptTemplate.from_messages([
    ("system", "Eres un asistente útil y amigable que mantiene el contexto de la conversacion."),
    MessagesPlaceholder(variable_name="historial"),
    ("human", "{mensaje}"),
])
```

- Pasamos el mensaje de sistema inicial (como una especie de "root prompt").
- Pasamos el `MessagesPlaceholder` recibiendo la variable de historial, la cual se compondrá de múltiples `HumanMessage` y `AIMessage` pasados previamente.
- Agregamos la nueva pregunta/prompt actual del usuario.

### Estructurar las Peticiones

Finalmente, para que el LLM reciba todo con el formato correcto, podemos pasar nuestras variables en el momento del renderizado, como por ejemplo usando el método `format_messages`:

```python
historial_conversacion = [
    HumanMessage(content="Hola, ¿Cual es la capital de Polonia?"),
    AIMessage(content="La capital de Polonia es Varsovia."),
    HumanMessage(content="¿Y cuantos habitantes tiene?"),
    AIMessage(content="Varsovia tiene aproximadamente 1.8 millones de habitantes."),
]

mensajes = chat_prompt.format_messages(
    historial=historial_conversacion,
    mensaje="¿Puedes decirme algo interesante de su arquitectura?"
)
```

Al inspeccionar los mensajes, el `MessagesPlaceholder` habrá inyectado eficazmente los 4 mensajes (Human y AI alternados) entre el System Message y la última pregunta del usuario, consiguiendo que el LLM actúe con memoria de contexto total sobre las consultas.

## Casos de Uso

1. **Memoria y Contexto en Chatbots:** Es la clase principal para pasar el historial de conversación en tiempo real al modelo y que pueda contestar acorde a los mensajes de la interacción previa.
2. **In-Context Learning (Few-Shot Examples):** Muy utilizado para proporcionar pares de ejemplos de preguntas y respuestas al LLM para "enseñarle" con unos pocos casos prácticos cómo debe reaccionar ante interacciones concretas antes de que provea su respuesta final.
